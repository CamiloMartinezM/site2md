# Take a fast path only where the output is the same

From 0.6.0, `build` skips work that a run doesn't need, under one rule: a shortcut is taken only where its result is exactly what the full path gives, and everywhere else the run falls back to the full path. Speed never changes the Markdown, the extraction result, a message or an exit status. Four shortcuts follow the rule. `main` binds a plain `build` command line itself, which is the input, `--name value` options and flags, and leaves every other command line to cyclopts, which draws the help and words every error. `build` prints a message without loading Rich when there is no progress bar and no terminal, where Rich only strips the styles; a message that Rich would wrap, or change in any other way, goes through Rich. The converter renders Markdown from the tree of the first parse, and parses the serialized content a second time, as 0.5.0 always did, only when the second parse could give a different tree. `main` puts a placeholder for Soup Sieve in `sys.modules` that imports the module at its first use, because Beautiful Soup imports it at start-up and only a CSS selector needs it. Together they save about 150 ms of a page build that took 625 ms with the package on Windows.

The price is two ways to do the same thing, which can drift apart. Tests through the installed command hold them together: the same build with and without a shortcut must print the same lines and write the same bytes, and the start-up tests record that a plain build loads neither cyclopts nor Rich. The fallbacks are broad on purpose. A parameter annotation that `main` doesn't know, a style that isn't in `_STYLE_TAGS`, a non-ASCII character and a line near the wrapping width all take the full path, so code that forgets a fast path gets slower, not wrong.

The alternatives were to replace the libraries or to accept small differences. `argparse` in place of cyclopts would change the help and the error messages. Without Rich there is no progress bar and no colour in a terminal. lxml builds different trees, and so different Markdown. Rendering from the first tree without the fallback changes the Markdown of a page with a doctype inside its content, and loses text with Beautiful Soup 4.12, the declared floor ([#59](https://github.com/CamiloMartinezM/site2md/pull/59)). Each changes what a user gets, so none was taken.
