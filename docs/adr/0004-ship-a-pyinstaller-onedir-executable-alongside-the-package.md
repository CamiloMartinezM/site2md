# Ship a PyInstaller onedir executable alongside the package

site2md ships a standalone executable for Windows x86_64 and Linux x86_64 next to the Python package, which stays the default install and doesn't change. The executable starts faster than a Python environment and needs neither Python nor pip, at the cost of a second distribution channel, a bundle of about 30 MB that people download and keep, and import errors that show up only at run time, so CI builds and smoke-tests it on every pull request. It is a PyInstaller onedir build on Python 3.12. Onefile would unpack itself at every start, which is the cost the executable exists to avoid. Nuitka and mypyc compile to C, which needs a C toolchain on every platform and a far larger build and test surface, and neither was measured. A zipapp still needs a Python installation and saved no time in the benchmark. Python 3.12 ran 8 to 18 ms faster than 3.14 in every prototype run and gets security fixes until October 2028; a later release moves to a newer Python.

The executable's interpreter starts isolated, so it ignores `PYTHONPATH` and can't see providers that pip installed elsewhere. It reads `SITE2MD_PROVIDER_PATH` instead: folders, separated as in `PATH`, that hold providers installed with `pip install --target`. Its entry script adds them with `site.addsitedir` after the bundle's own folders and before discovery runs, so bundled modules win and `.pth` files in the folders are processed. The package doesn't read the variable. Reusing `PYTHONPATH` would make the executable scan every package on a global path at each extraction, and a second copy of site2md there would conflict with the built-in Extractor. The limits of this arrangement are documented, not removed: only the standard-library modules that the bundle includes are available, compiled code must be built for Python 3.12 on the same platform, and a provider can't replace a library that the bundle already has. Anyone who hits a limit uses the package, and modules are added to the bundle only when a real provider needs them. There is no macOS build, because Gatekeeper blocks unsigned binaries and notarizing needs a paid Apple developer account, so macOS users keep the package. The Linux build runs on the oldest Ubuntu runner that GitHub offers, so that it works with older glibc.
