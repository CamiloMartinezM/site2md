# site2md 0.7.0

Version 0.7.0 adds `build --browser`, with `--wait-for`, `--browser-profile` and `SITE2MD_BROWSER`, and fixes six bugs in what `build` prints, writes and accepts. Without `--browser`, a build makes the same requests as in 0.6.0. A page converts to the same bytes unless it holds a formula or a list of paragraphs.

## New: `build --browser`

A plain build converts the HTML that the server sends. A page that fills itself in with a script arrives empty, so a plain build saves its frame and reports success. On the [Oscar Winning Films](https://www.scrapethissite.com/pages/ajax-javascript/#2015) practice page, it writes the table's header and no rows. `--browser` loads the page in a Chrome, Edge or Chromium that is already installed, lets the page's scripts run, and converts what the browser then shows. The same page then has its 16 rows ([#96](https://github.com/CamiloMartinezM/site2md/issues/96), [pull request #101](https://github.com/CamiloMartinezM/site2md/pull/101), [ADR 0006](adr/0006-read-script-built-pages-from-an-installed-browser-only-when-asked.md)).

- **The command.** `site2md build URL --browser` is for page mode and an `http://` or `https://` URL. With follow mode, site mode or a local folder it fails before any request. It adds no dependency, and the executable has it too ([#97](https://github.com/CamiloMartinezM/site2md/issues/97)). Without `--browser`, a build makes the same requests and doesn't load the browser module.
- **Which browser: `SITE2MD_BROWSER`.** The program that the variable names, if it is set. Otherwise Chrome, then Edge, then Chromium, where each system installs them. site2md installs and downloads no browser. Without one, the build fails with one line that names the variable.
- **When the page is read.** After 10 seconds of the page's own time. The browser fast-forwards the page's timers and holds its clock still while a request is under way, so a page that waits two seconds before it asks for its data doesn't cost two seconds. No option sets that budget.
- **`--wait-for SELECTOR`.** It reads the page as soon as an element matches the CSS selector, in real time and without that budget. Use it for a page that keeps a request open, because the page's own time never gets past one. If no element matches within the 30-second timeout, the build fails with one line that names the selector. A selector that the browser doesn't accept fails before any request. It needs `--browser` ([#98](https://github.com/CamiloMartinezM/site2md/issues/98)).
- **`--browser-profile FOLDER`.** The browser uses the folder as its profile instead of a temporary one, and the folder stays. If a session is in it, the page is read as the signed-in visitor sees it. You start the same browser with `--user-data-dir=FOLDER`, sign in and close it, because site2md has no window of its own for signing in. It needs `--browser` and an existing folder ([#99](https://github.com/CamiloMartinezM/site2md/issues/99)).
  - The folder can't be the profile that you use every day, because Chrome refuses remote debugging on it, and no other browser may have it open.
  - site2md never removes, empties or copies anything out of it, also not with `--keep-temp`. It holds your session, so treat it like a password.
  - Without the option, each build uses a new temporary profile. It is removed afterwards with every browser process, also after a failure or an interruption.
- **What stays as in a plain fetch.** Only a final `2xx` response of type `text/html` or `application/xhtml+xml` is converted, by its `Content-Type` header. Redirects are followed, and an HTTPS-to-HTTP move is refused whether a server, a script or a meta refresh makes it. The 30-second timeout runs from starting the browser to reading the page, and `--max-page-size-mib` limits the page as the browser shows it. The address that the browser ends on is the source, so the source marker and the links are those of a plain build. A failure gives the same line, and an existing output file stays as it was.
- **What the browser loads.** Everything that the page asks for, as any browser does: its scripts, style sheets, fonts, images and data, from its own host and from others, and its icon. Nothing is blocked, and nothing checks `robots.txt`, because the page is a direct request and these requests belong to it. A plain build makes one request. A `--browser` build makes many, to hosts that you didn't name.
- **What it says.** The User-Agent is the browser's own, `HeadlessChrome` included, followed by ` site2md/0.7.0`. Every request that the browser makes has it: the page's, those of a frame of another site, the page's icon, and a service worker's script and requests.
- **What is out of scope.** `--browser` doesn't hide that the browser is automated, and it doesn't answer a browser check, a CAPTCHA or any other defence of a site. The browser keeps its sandbox, and site2md never passes `--no-sandbox`. Downloads are refused and dialogs are dismissed. It doesn't click, type or scroll, and it doesn't read frames or shadow roots. Content that the page hides with CSS still comes out. Follow mode, site mode and local input don't use a browser. It works on Windows and Linux, and macOS isn't promised.

The README has the same rules under [Read a page that a script fills in](../README.md#read-a-page-that-a-script-fills-in) and [Read a page that only signed-in visitors get](../README.md#read-a-page-that-only-signed-in-visitors-get). Use both options only on sites whose terms allow automated access.

## Fixed

- **`build`'s messages and bracketed text** ([#85](https://github.com/CamiloMartinezM/site2md/issues/85), [pull request #101](https://github.com/CamiloMartinezM/site2md/pull/101)). `build` printed the paths, URLs and error text that it was given as if they were Rich markup. A bracketed word such as `[draft]` vanished, a backslash before a bracket vanished, and a `:name:` that names an emoji became the emoji. A build of `pages[draft]` to `notes[final].md` said that it wrote `notes.md`. A `[/x]` in a link made a site build write its output and then end with a traceback and exit status 1. Now every message shows the text as it is, and that site build prints its warning and exits 0. The files that `build` wrote were right. Local builds had this since 0.2.0, and the warnings of follow and site builds since 0.4.0.
- **TeX formulas in page text** ([#92](https://github.com/CamiloMartinezM/site2md/issues/92), [pull request #104](https://github.com/CamiloMartinezM/site2md/pull/104)). A formula that a page holds as text came out changed: `$$a_1 * b_2 = c_3$$` became `$$a\_1 \* b\_2 = c\_3$$`. In TeX, `\_` is a literal underscore, so a subscript was gone, and a viewer that renders formulas showed another formula. Now `$…$`, `$$…$$`, `\(…\)` and `\[…\]` are written as the page has them. The text around a formula is escaped as before. `$…$` follows pandoc's rule, so `It costs $5 for one and $10 for two` is prose.
- **Rendered formulas** ([#93](https://github.com/CamiloMartinezM/site2md/issues/93), [pull request #107](https://github.com/CamiloMartinezM/site2md/pull/107)). A page whose formulas a library had already rendered lost their structure, and some were written twice or three times. A half, `<mfrac><mn>1</mn><mn>2</mn></mfrac>`, came out as `12`, and a KaTeX formula for x with subscript i as `xix\_{i}xi`. Now each formula is written once, as TeX between dollar signs. A display formula goes between `$$` and `$$`, in a paragraph of its own.
  - **KaTeX**, and any `<math>` element with an `application/x-tex` annotation: the author's TeX from the annotation.
  - **MathJax 2**: the author's TeX from the `<script type="math/tex">` next to the rendered formula, also with `mode=display`. Every other script is still removed, and the rendered copy of the formula is dropped.
  - **MathJax 3 with assistive MathML**, and **plain MathML**: TeX built from the MathML. The elements `mi`, `mn`, `mo`, `mtext`, `mrow`, `msub`, `msup`, `msubsup`, `mfrac`, `msqrt` and `mroot` are converted, and so is `mathvariant="double-struck"`. A half is `$\frac{1}{2}$`.
- **Lists whose items are paragraphs** ([#94](https://github.com/CamiloMartinezM/site2md/issues/94), [pull request #106](https://github.com/CamiloMartinezM/site2md/pull/106)). `<li><p>…</p></li>` is a loose list, which a browser shows with space between the items. `build` wrote its items on consecutive lines, which Markdown reads as a tight list. Now a blank line separates the items. A list is loose when at least one of its items has a `<p>` as a direct child, and each list is decided by itself, so a tight list inside a loose one stays tight. Numbers and bullets don't change.
- **A redirect that ends at an intermediate page** ([#95](https://github.com/CamiloMartinezM/site2md/issues/95), [pull request #105](https://github.com/CamiloMartinezM/site2md/pull/105)). A redirect to a sign-in page, a consent page or a browser check was followed and converted, and `build` printed `Success!` and exited 0. The Markdown held that page instead of the one that was asked for, and in follow and site mode each redirected child added another copy that counted as fetched. Now site2md refuses such a page and doesn't answer it.
  - **How it is recognised.** After redirects, a response is an intermediate page when a parameter of its final URL has a value that, percent-decoded, equals the requested URL, or the requested URL's path with its query. A request to `https://example.com/articles/one` that ends at `https://example.com/login?return_to=%2Farticles%2Fone` is one. A response that wasn't redirected never is.
  - **An entry page** that ends at one fails the build in every remote mode, with one line that names the requested URL and the final URL. The exit status is 1, and an existing output file stays as it was.
  - **A child** that ends at one gives a warning that names both URLs and counts as failed. Nothing from it is converted or followed, and the traversal goes on. The warning's wording isn't a promise, but the two URLs in it are. `--browser` applies the same rule to the address that the browser ends on.
- **Requests of `--browser` without the User-Agent suffix** ([#103](https://github.com/CamiloMartinezM/site2md/issues/103), [pull request #108](https://github.com/CamiloMartinezM/site2md/pull/108)). While `--browser` was built, the icon that a browser asks for after a failed build and a service worker's script reached the server without ` site2md/<version>`. No released version had this, because `--browser` is new in 0.7.0. Now every request that the browser makes has the suffix. When a build ends, also when it fails, site2md closes the page and its service and shared workers before it closes the browser, so that nothing is asked after the browser has stopped saying who it is.

## What changes when you upgrade

No option or default of 0.6.0 changes. The three new options need `--browser`, which is off by default.

- **The Markdown of a page with formulas or lists of paragraphs is different.** A page without them converts to the same bytes as in 0.6.0, and so does text with dollar signs that is no formula.
  - A formula comes out unescaped. A reader that doesn't render TeX can read a pair of `*` or `_` inside a formula as emphasis. That is the price of a formula that is right.
  - A `<math>` element that the converter has no rule for stays in the Markdown as the page wrote it, attributes included. It is the first element that the converter copies from a page as HTML, and a viewer that doesn't sanitise raw HTML renders it.
  - A MathJax 2 `<script type="math/tex">` is read and not removed. A page that was saved before MathJax 2 ran, and holds only that script, now has the formula.
  - A list of paragraphs has a blank line between its items.
- **What an Extractor reads is different.** The node kinds are the same, and none is added.
  - A formula is one `text` node that holds its characters as written, delimiters included, with no emphasis inside it: `$a*b*c$` gives the text `$a*b*c$`. An Extractor that looked for `emphasis` inside a formula, or counted on a backslash in `\(`, `\[` or `\{` being dropped, sees other text. A `<math>` element that the converter keeps is read like any inline HTML.
  - After a loose list, line numbers and offsets move: every blank line that the converter adds puts the lines below it one line lower, and the `list` node spans more lines. A list item holds a paragraph node in a tight list and in a loose one.
- **A build whose entry page ends at an intermediate page now fails.** It exits 1 where it exited 0 and wrote the sign-in page. In follow and site mode a child that ends at one now gives a warning and counts as failed, so a site that does this has fewer pages in the document and a higher `failed` count. The build still exits 0.
- **`build`'s messages show bracketed text as it is.** A script that matched the wrong text, such as `notes.md` for `notes[final].md`, sees the right text. A site build that ended with a traceback now exits 0.
- **With `--browser`, the page and its workers are closed before the browser.** A page's own `pagehide` and `unload` handlers therefore run if the page had loaded, and what they ask has the User-Agent suffix too. A build that fails before the page's load event closes the page without them. Closing the browser under the page never ran them.
- **The User-Agent is `site2md/0.7.0`.** A plain fetch sends it, and `--browser` appends it to the browser's own.

## Limits

- **The two limits of the intermediate-page rule.** A sign-in redirect that carries no return address isn't recognised, and its page is converted. A redirect to the real page that also carries the old address as a parameter is refused. The [traversal policy](traversal-policy.md#intermediate-pages) states both.
- **MathML without a rule** stays in the Markdown as the page's `<math>` element, in HTML. A formula with any element or `mathvariant` outside the lists above is kept that way, and so is one with a backslash, `^` or `~` in a token. A `<math>` element with a TeX annotation is never kept: the author's TeX is written.
- **MathJax 3 without assistive MathML.** It can be set up that way, and its SVG output draws paths. Such a page holds no text for a formula, so the formula isn't in the Markdown.
- **Only a formula inside one text node** is read as a formula. One that an element splits, such as `$a_<em>i</em>$`, is still escaped as prose.

The [0.4.0 release notes](release-0.4.0.md) still describe the remote modes and their limits, except that page mode can now read a page from a browser, with a signed-in session if you give it a profile. Follow and site mode still can't. Publishing to PyPI or another package registry remains a separate maintainer action.
